# MCP门户技术设计

关联：用户原话见discovery/survey.md，角色/模块/行为/契约见prd/portal.md。治理记录为本任务before/run/after，不修订旧任务结论。

## 组件和契约

- 3029：Starlette说明门户与唯一所有者登录，直接使用现有私有CA签发的IP服务器证书，uvicorn禁用proxy_headers；只绑定10.8.61.200，实际TCP源需属于10.8.0.0/16。公开/、guide和固定下载白名单；管理/admin、/issue、/revoke独立会话认证。
- 管理口令：.secrets/token-desk-admin.json，只存600000次PBKDF2-SHA256摘要与随机盐；初始随机口令仅保存在受限服务器文件。配置丢失、形状异常或摘要错误则管理关闭。每次会话授权绑定当前凭据文件摘要；更换凭据使旧会话失效。
- 登录：10分钟单次挑战与Secure/HttpOnly/SameSite=Strict预登录Cookie双重绑定；同源Origin+Host、最大4096字节表单、禁止重复字段；每个实际TCP源5次失败/15分钟；并行KDF限制2，会话与挑战数量有界。
- 管理会话：随机256位不透明Cookie，服务只存其SHA256索引；空闲20分钟、绝对8小时，退出、服务重启或凭据变更失效；CSRF逐会话随机，不存于共享页面。浏览器离页清空一次性令牌显示。
- 令牌：保留现有.secrets/mcp-server.json为唯一认证权威。线程RLock与跨进程文件字节锁保护读改写；唯一临时文件、fsync、os.replace。签发先写元数据再提交认证文件；撤销先提交认证文件，元数据失败不阻止紧急撤销。撤销所有令牌是合法状态，MCP之后全部拒绝认证。正在执行中的请求不作取消。
- 配置损坏：重复JSON键、无效对象/身份/重复token/不安全token形状均拒绝；签发不重新创建丢失配置。MCP每次请求加载文件，任何读取或验证异常返回空令牌表，禁止回退启动令牌。
- 下载：只发布预定的CA公钥、schema、无凭据示例、协议/SDK客户端、逐工具参数和指南。无目录浏览，无文件路径透传，无身份列表或动态令牌下载。CA PEM文件SHA256与证书DER指纹分别命名。
- 3037：继续原生MCP，2025-11-25已验证、JSON响应、无状态；源/统计查询继续调用回环3036 API。仅修正文档和Schema参数约束一致性，不改业务聚合和数据库。

## 失败、风险与回滚

首次CA信任需要可信渠道交付文件和指纹；来自未信任TLS站点的下载本身不建立信任。所有接收人的有效令牌仍拥有相同的只读来源范围；这是既有边界，不宣称逐来源ACL。持有Bearer可读取客户内容；静态下载包不授予此权限。

3030和3036不重启，watch不启动，allow_production_read=false不改变。旧备份位于.runtime/mcp-portal-backup，仅代码和公开配置，不包含秘密。发生运行故障，先关闭Portal3029防火墙规则、停止desk，恢复已知代码后只在回环运行旧管理页；不能在内网开放旧匿名管理页。MCP可单独恢复代码，但不能恢复旧token文件或已撤销凭据。

观察：以两端口严格TLS、匿名权限、管理员签发→真实MCP调用→撤销→401、全部11工具、14表目录和分页、下载哈希与无秘密扫描作为发布验证。正式independent-review/security-privacy-review仍需要真实决定，不把测试或用户继续指令伪装为最终门禁通过；工程和人的验收分别留档。
