# 客诉日报 PRD v2

## 目的与角色
研发、运营通过昨日邮件定位具体问题、规模变化和核对证据；本机验收人在127.0.0.1:3030使用独立单页。MCP、令牌服务及对外交接说明按用户指令交给独立会话，当前任务只保留已修复缺陷的核验记录。

## 范围与口径
覆盖2026-10-29北京时间全天634封RECEIVED邮件，一封一主组，次问题单列。正文优先，三级系统分类作为参考。每封都保存中文摘要、具体主题、判定依据、原分类、源主键、源版本、审查者和内容摘要。区分本封负面反馈、纯咨询/已解决回访、信息不足，全部可查询。来信数不能称作玩家数；跟进邮件不称新增独立事件；不推定技术根因。源摘要缺失时由本次逐封审查补齐并标注来源。

## 页面结构
1. 全宽标题、日期、快照与隔离状态。最新视觉依据为用户提供的《2026-10-29 客诉日报2.html》；固定白色背景，采用红紫青绿语义色、紧凑边框与8px圆角，保持用户先前要求的全屏宽度。
2. 标题下先显示有依据的日报结论，顶部只展示三项核心指标：来信量、日环比、前7日均值对比。逐封审阅与附件覆盖在标题和口径面板保留。
3. 问题排行：按业务领域显示数量与占比；Top10具体客诉以可点击排行行、条形量级、总量占比、集中子问题展示。附所有主问题的领域标签→主组→子问题筛选，避免211个平铺标签妨碍浏览。领域只用于导航；主问题仍按可行动的现象区分，存储不足、进度归零、黑屏、加载停滞分别保留。相近子问题有证据才合并，混合的原始叶子先逐封纠偏，未知原因不进入具体问题Top10。
4. 所有问题组及证据清单：时间/主键、发件与实际送达邮箱、主题及逐封摘要、正文、UID及依据、原系统三级分类、日志、图片、其他文档、详情入口。适配参考表格的密度与收发邮箱堆叠样式，全部字段保留；搜索、领域/主组/子问题/口径筛选、分页。主题/正文两列独立切换原文译文。
5. 补充指标与收件图移到原信明细和分页之后：先显示已归类来信、昨日收件高峰、单一UID文本证据三项，再显示15日收件趋势和昨日24小时收件量两列图表；窄屏依次堆叠。小时点击继续筛选原信并回到明细，所有统计口径与数值保持原样。
6. 叠加侧栏：完整邮件内容、会话UID证据、所有附件与预览、复查元数据。附件列先预览一个，点击打开侧栏展示全部。图片/日志真实字节预览；文档按安全类型预览或下载，不能把二进制显示成文本。HEIC生成本地预览副本，原件保留。视频显示可播放预览或格式说明。缺失/损坏给出明确状态。

## 约束与验收
- 保留现有文件结构和命名，只增加职责明确的报告/下载适配器及静态资源；不引入Next服务或外部前端CDN。
- 报告先生成稳定读取模型，页面请求不扫描数据库、不做复杂聚合；只读本地快照。
- 下载器只读取原邮箱，经TLS使用EXAMINE与BODY.PEEK；核对UIDVALIDITY、Message-ID、附件内容摘要；白名单限定这405条，不更改源库或邮件状态。私有凭据留.secrets，不进入日志、网页、导出。
- 3030仅回环，检查真实客户端/Host/Origin，禁代理头放行；文件按固定ID索引，只读交付，禁止路径穿越/主动HTML执行。
- 每封有摘要；源缺译文时说明或提供本次译文来源，不冒称源系统译文。UID先核对结构化字段与原文，缺失时仅沿同采集邮箱的真实Message-ID / References / In-Reply-To链和参与者范围补充；thread_id、相同发件人、业务问题组不能单独形成会话；多账号角色、历史值冲突不自动选择。文本支持不等于验证账号持有人。
- 参考HTML含示例正文与附件生成代码，只借用视觉和布局，不导入示例数据，不执行原文件脚本。所有正文、UID、分时数量、附件均来自当前真实副本与受审查记录。
- 634封主组计数和占比闭合；图表/过滤/分页/叠加栏/译文按钮/日志图片预览均实测。附件不足时如实列未完成，不以文件名代替完成。
- 生产隔离后无法证明当前线上完全一致；不得宣称已在日终1小时内重新完成采集或完成线上全量核对。
- 工程验证与需求方验收分开，需求方决定Pending，原型和最终页面等待用户实际评价，不补造通过。
