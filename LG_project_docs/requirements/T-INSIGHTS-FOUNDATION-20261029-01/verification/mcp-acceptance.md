## 实际结果

- 原有 38 项加 9 项 MCP/源记录契约检查，共 47 项通过，日志摘要见 `mcp-results.json`。
- 真实 TLS 连接使用随包 CA 严格验证 IP、签名链和证书摘要；没有跳过证书校验。
- MCP 列出 11 个只读工具；原始十四类资料逐类读取并与独立只读 SQL 结果核对。
- 真正执行旧版 `2025-06-18` initialize，并完成当前 SDK 协议工具调用；没有把 SDK 的兼容说明当作本机验证结果。
- 未带/错误 MCP 令牌返回 401；非允许来源、明文请求与伪造代理来源的中间件检查通过；真实错误 Host/Origin 返回拒绝。
- 游标与筛选、来源及数据版本绑定，非法表名、超限、错误主键、参数和 SQL 注入拒绝通过。
- 原始资料默认仅取主键和同步元数据，显式请求才返回完整 payload；正文按需读取。
- 数据源、MCP 访问、SQL reader 和本地 API 凭据分开，日志只保留元数据；没有将数据发送给第三方模型。

## 失败与修复保真

首次生成的证书缺少 SKI/AKI，Python 3.13 严格 TLS 校验报 `Missing Authority Key Identifier`，该次连接失败。随后修正证书生成器，在保留密钥、令牌和失败公开证书证据的前提下补齐扩展，重启本项目 MCP；真实严格 TLS 和完整调用验证通过。原失败证书与端点摘要保存在受保护 `.runtime/tls-before-repair/`，没有隐藏失败或关闭校验。
