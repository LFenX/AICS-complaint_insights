## 工程测试

- 38 项单元及真实 PostgreSQL 隔离集成测试通过，覆盖时间、分类、多问题去重、权限、API、来源隔离、事务回滚、日志恢复和源契约变化。
- 测试源和测试目标均为新实例内随机命名数据库，已清理；没有对现有开发源执行破坏性测试。
- 原始源与副本的十四张业务表按行重新计算 SHA256 并比较，不使用同步器缓存的内容指纹作为唯一判据。`messages.last_fetched_at` 是明确排除的抓取心跳字段，其他内容均参与比较。
- 真实 TCP/HTTP 服务验证覆盖九个端点、鉴权拒绝与完整原始行读取；进程停止后 3036 不再监听，恢复后正常响应。
- 初次导入约 52 秒；一次无变化辅助对账约 0.83 秒；正常无变化事件轮次约 0.29 秒。这些是开发环境实测，不是生产性能承诺。

结构化结果见 [results.json](results.json)。私有测试原始日志位于 `.runtime/unittest-final.log`，公开结果只包含计数、摘要和指纹，不包含客户内容、密码或 Token。

## 安全隐私门禁待审材料

已实测：源事务只读；目标 reader 即使关闭默认只读也无写权限；没有物理镜像 schema 的直接权限；API 未授权为 401、写路由为 405；SQL 和底层 API 仅回环监听；生产默认禁止；私有目录使用当前用户/SYSTEM ACL；分析凭据不包含源或 owner/writer 连接。

开发源账号沿用已有配置，其数据库账号本身的既有权限未被修改；采集器通过连接和事务强制只读。生产专用角色仍需实际接入验证。副本保留删除标记和归档，不等于物理擦除。数据没有发送给外部模型或其他分析服务。

`security-privacy-review` 的正式决定须由用户作出。不能将以上自动测试或 Agent 的说明写成用户已经批准。
